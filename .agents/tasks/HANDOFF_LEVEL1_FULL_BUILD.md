## 0. What Level 1 is (one paragraph)

One continuous ride, ~5–6 minutes, where the rider **is the signal** inside a neural network that learns to read a
handwritten **3**. No spaceship, no AURA, no JFK, no history lecture. Eight regions blend like biomes, each with its
own look and sound: **the Page** (a real handwritten 3 on paper) → **the Grid** (its pixels as glowing pillars) →
**One Neuron** (the rider paints a neuron's weights so it fires for 1s and not 0s) → **the Network** (49 inputs, 16
hidden, 10 outputs) → **Wrong** (the untrained network guesses wrong) → **Rewind** (the cart reverses as the error
flows backward: backpropagation) → **the Valley** (an automatic coaster drop down the real error landscape: gradient
descent, with one overshoot) → **Right** (same 3, trained weights, it says "3"; teaser: the same machinery with words
is how chatbots work). Every section: **explain first, then a matching minigame or moment**. Everything that glows is
what the math computes: the network is a real tiny network trained offline on real MNIST.

## 3. Hard rules (break none of these)

1. **The scene is generated.** All scene, prefab and material changes go through `Tools/Editor/NeuralRideBuilder*.cs`
   and a rebuild. Never hand-edit `NeuralRide.unity` or the prefabs; never save the scene after a capture.
2. **Layers** (`AGENTS.md`): `Core.*` is plain C#, no UnityEngine. Puzzle correctness and all network math live in
   Core. `Gameplay` orchestrates (MonoBehaviours, may use JsonUtility) but implements no NN math. `XR` turns input into
   gameplay commands and never evaluates. `Presentation` only displays. Never hardcode puzzle completion.
3. **Honesty**: the network is real (trained offline on real MNIST, weights baked as data). The "wrong" pass uses the
   real untrained initial weights; the "right" pass the real trained weights; blame = real gradients from Core
   `Backward`; the Valley = the real loss surface and the real training run. Every number the narrator says
   (the wrong guess, the accuracy, the digit count) comes from the bake. If the data disagrees with the script,
   change the script, never the data.
4. **Orange means "you can grab or press this"** (`RideTheme.orange`). Nothing else may be orange, including the
   sunset in the Valley (use pink/violet/crimson there).
5. **Comfort** (first-time VR users): yaw-only rotation of the cart, eased starts/stops, nothing passes within 1.5 m
   of the head, the cockpit tub always in view. The cart never pitches or rolls, even on the drop (vertical
   translation only, capped acceleration). A **gentle mode** halves drop height and speed.
6. **Quest 2 budgets** in every viewpoint: ≤ 100 draw calls, ≤ 100k triangles, 72 fps. No post-process bloom, no
   real-time shadows (ADR-013). Use the existing `HoloLit`, `NeuralLinks`, `NeuralNodes` shaders and combined meshes.
7. **Prove with pixels and numbers.** After any visual change: seat captures (1.15 / 1.30 / 1.45 m eye, gaze yaw
   −30/0/+30) + model sheets of every new/changed model, and look at them. `vr-qa` subagent does the second read.
8. **You cannot hear.** Never judge voice or music quality; render, verify by transcription, ask the owner to listen.
9. **Tests**: never delete or weaken a failing test to go green. Tests of removed content (the old stops) are
   **replaced** by tests of the new flow in the same change, and the replacement is noted in the task file.
10. **Narration ids**: `RideLine` values 1–31 never change number. New Level 1 lines are **appended** (32+).
11. **Packages**: none added or upgraded without an ADR. Asset Forge (AI 3D models) is paused until after 10-20.
12. **Ask, don't guess** for the owner gates in section 5.

## 4. Tooling cheat sheet (learned the hard way on this machine)

Windows 11, Unity **6000.6.0f1**, URP, OpenXR, XRI 3.6, project color space **Gamma**. Bash and PowerShell both exist.

**Unity CLI** (`unity`, v1.0.0-beta.12) drives the open Editor. The `unityMCP` MCP server was **down**
(ECONNREFUSED) last session; the CLI works and is enough.

```bash
unity status --format json                      # Editor state must be "ready"
unity recompile --format json                   # compile; returns errors/warnings summary
unity command eval '<C# returning a value>' --result-only -- --timeout 600000   # long calls: eval's own timeout (ms) after --
unity command run_tests --format json -- --mode EditMode     # (or PlayMode) runs tests IN the open Editor
unity command editor_play / editor_stop / set_autotick
unity command console                           # captured console output
unity list                                      # every command the Editor exposes
```

- After `unity recompile`, a domain reload follows: poll `unity status` until `ready` before the next call.
- `unity test ...` **refuses** while the Editor has the project open. Use `unity command run_tests`.
- Play Mode on an unfocused Editor can freeze at frame 1–2. Run `unity command set_autotick` first and check
  `Time.frameCount` advances.
- Build the ride: `unity command eval 'Convergence.EditorTools.NeuralRideBuilder.Build(); return "built";' --result-only -- --timeout 600000`.
  It throws on any failed assertion (sightlines, audio levels, model-sheet coverage): read the message, fix the cause.
  Each build recreates mesh assets (new GUIDs), so prefab diffs after a build are expected.
- Captures: `Convergence/Capture Ride Seat Views` (edit mode, scene must be saved/clean),
  `Convergence.EditorTools.RideLiveShot.Shoot(path, eye, fov, yaw, pitch)` (Play Mode),
  `Convergence.EditorTools.RideModelSheets.Capture()` or `Capture("id1,id2")` (edit or Play Mode).
- Validators: `pwsh` is **not installed**. Use
  `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Validation/Validate-CoreBoundaries.ps1` (and
  `Validate-RepositoryLayout.ps1`).
- Long Python edits through a bash heredoc broke once on quoting. Write helper scripts to the session scratchpad and
  run `python -I script.py`. Python 3.13 and `uv` are installed (`uv run --with numpy python -I ...`).
- Rendering facts: the project is Gamma, so render textures use `R8G8B8A8_UNorm` (sRGB warns). Scene fog also
  applies to preview scenes; toggling `RenderSettings.fog` in code does not dirty the scene. `NeuralLinks`/`NeuralNodes`
  fade out beyond ~95 m (`_FarStart/_FarEnd`) and inside ~1.6–4.2 m, and clamp line width in pixels.
- TMP labels are one-sided (mirrored from behind) and the network's additive lines cross them unless a solid
  backing sits behind (`LabelBacking`, material `PlateSolid`).

## 6. The design to build, region by region

Track total ≈ 5–6 min. Region roots in the scene are named `Region_0` … `Region_7` (the model-sheet coverage check
already recognises `Region_` roots). Each region has a palette, fog colour/density, ambient sound/music layer,
and a **region tag** (small label, e.g. "2 · ONE NEURON", lower-left of view) instead of the old chapter cards.

| # | Region | Look (palette suggestion) | Teaching moment | Interaction | Target length |
|---|---|---|---|---|---|
| 0 | **The Page** (dock) | Warm paper `#F3EBDD`, ink `#1B1B2F`, daylight fog, the only bright region | A giant sheet with the real handwritten 3 (hero digit from the bake) | Pull GO: the 3 lifts off and breaks into pixels; the cart dives in | 30 s |
| 1 | **The Grid** | Black void, white pillars `#F5F7FF`, faint cyan rim | 28×28 pillars, height = ink brightness (0…1). Then the field condenses 4×4 → **7×7 = 49 numbers**, "all the machine gets" | Watch: ride low over the pillars | 25 s |
| 2 | **One Neuron** | Deep warm dark, one huge amber neuron `#FFB547` | Weights: + = "I want ink here", − = "I don't"; multiply, add, fire past the line | **Paint the weights** (7×7 grid, tap cycles 0 → + → −). Goal: fire for 1s, not for 0s. Real 7×7 test digits roll past; each shows *why* (per-cell ink × weight, the sum vs the line) | 90 s |
| 3 | **The Network** | Vast cool blue `#4FC3FF` on navy; must read as layers even from far | 49 inputs → 16 hidden → 10 outputs labelled 0–9; wires coloured by sign, width by size of weight (**untrained** weights) | Watch: the hero 3 races layer to layer; node brightness = real activations | 35 s |
| 4 | **Wrong** | Network flickers red `#FF3B3B` | The untrained guess (from the bake, e.g. "8") lights up; "never been taught, weights are random" | Short dramatic beat | 10 s |
| 5 | **Rewind** | Magenta `#FF2BD6` / crimson | The cart **reverses**; error flows back; each wire burns by its real blame `|∂loss/∂w|`: backpropagation | **Find the blame**: point at the brightest wires to nudge them (one real gradient step on those weights; glow fades). Cut line: watch-only | 45 s |
| 6 | **The Valley** | Sunset pink→violet (`#FF6F91`→`#6B2D8C`, no orange), dark terrain with contour lines | Terrain = real loss over the plane the training run moved in; lower = less wrong: gradient descent | **Automatic coaster drop** along the real run: step 1 too big (overshoots up the far slope, loss really rises), then steps settle into the valley. Dash shows real step/loss | 40 s |
| 7 | **Right** | Back in the network, steady gold `#FFD166` | Trained weights, same 3 → "3". Real test accuracy and training count from the bake. Teaser: digits dissolve into words | End card + credits + "Level 2: words" teaser | 45 s |

**Track shape (recommended: a switchback, so the rewind never needs a jump or a turn-in-place):**
Leg A: dock (Page) → Grid → Neuron → **junction J** → through the Network → outputs (Wrong, stop).
Leg B: the cart rolls **backwards** along Leg A from the outputs back through the network, past J, onto a short
dead-end spur behind J (Rewind). The rider keeps facing the network, so it recedes: that reads strongly as
"backwards". Leg C: from the spur end the cart moves forward again, the switch at J sends it onto a branch (≤ 25°
eased yaw) that climbs to the Valley rim, drops, and climbs back into a high lane through the (now gold) network to
the finale. Keep the motion comfort rules (section 3.5).

### 7.1 Data bake (offline, Python): `ArtSource/training/bake_level1.py`

Follows the `ArtSource/voice` and `ArtSource/sfx` convention (a pipeline script beside its source data). Add the
folder to `ArtSource/AGENTS.md`'s layout table; git-ignore the raw MNIST cache (`ArtSource/training/mnist/`).
Run: `uv run --with numpy python -I ArtSource/training/bake_level1.py --out Assets/_Project/Data/Level1/level1_digits.json`.
NumPy only, fixed seeds, deterministic. Prints a summary table and **fails loudly** on any check below.

- **Source**: MNIST 60k train / 10k test (e.g. the `https://storage.googleapis.com/cvdf-datasets/mnist/` mirror),
  cached in `ArtSource/training/mnist/`. Licence: Yann LeCun & Corinna Cortes, CC BY-SA 3.0: add to the credits.
- **Input**: 28×28 → 7×7 by 4×4 average pooling, values 0..1 (0 = paper, 1 = ink).
- **Network**: 49 → 16 → 10. Activations must be ones Core reproduces **exactly**: check how `LayerModel.Forward`
  handles `ActivationType.Softmax` (layer-wide or per neuron). If softmax is not layer-wide in Core, use sigmoid
  outputs + mean squared error in the bake instead. Hidden: sigmoid or tanh (Core has both).
- **Training**: plain full-batch **gradient descent** on the 60k train set (the narration says "gradient
  descent"; keep it honest), enough steps for good accuracy at 7×7 (expect roughly 85–90 % test accuracy; report the
  real number). **Step 1 uses a too-large learning rate** chosen so the loss after step 1 is **higher** than before
  (the overshoot); verify it, then continue at the normal rate.
- **Hero digit**: a clear test-set "3" that the trained net gets right with high confidence (> 0.8) and the untrained
  net gets **wrong**. Pick the init seed so this holds; record `untrainedGuess` (the narrator says it).
- **Neuron puzzle set** (region 2): 4 real "1"s and 4 real "0"s (7×7), threshold T chosen so (a) the empty grid
  fails, (b) "paint everything +" fails (0s have more ink, so they fire too: this teaches negatives), (c) a known
  solution in {−1, 0, +1} passes all 8 (e.g. + down the middle column, − on the ring). Store `referenceSolution` **for
  tests only**.
- **Valley**: PCA of the parameter trajectory (top-2 directions, the "visualizing the loss landscape" method), a
  41×41 grid of real loss over that plane through the final weights (a 10k-sample subset is fine; say so in `meta`),
  the trajectory projected onto the plane, and the real loss at each recorded step. Choose ~12 "hops" for the ride:
  hop 1 = the single big step, then evenly spaced groups of real steps (record how many real steps each hop is).
  Report the PCA explained variance and the worst gap between surface height and true loss at the hops.
- **Finale**: ~60 test digits with the trained net's real predictions (for "many digits flow through").
- **Write** flat arrays with shapes (JsonUtility cannot read jagged arrays): `w1[16*49]`, `b1[16]`, `w2[10*16]`,
  `b2[10]` for both `initial` and `trained`; golden activations of the hero digit for both weight sets (used by the
  test that Core reproduces the bake to 1e-6); `trainCount`, `testAccuracy`, seeds, numpy version, date, source, licence.

### 7.2 Core (plain C#, run `Validate-CoreBoundaries.ps1` after every Core change)

- `Core.Puzzles/WeightPaintPuzzle.cs`: inputs = digits (49 values each), should-fire flags, threshold. `Evaluate(int[49]
  weights in {-1,0,1})` → per digit: sum, fired, correct, per-cell contribution (ink × weight); `Passed`.
  `Hint(weights)` → the one cell change that most improves the number correct (tie-break: biggest margin), computed
  from the evaluator, **no stored answer**, so it works from any state.
- `Core.Neural`: a factory that builds a `NetworkModel` from flat arrays + shapes + activations (if one does not
  exist). Blame uses the existing `Forward` → `Backward(dLoss/dOutputs)` and `NeuronModel.GetWeightGradient(i)`.
- **EditMode tests** (`Tests/EditMode/Core/`): reference solution passes; empty and all-plus fail; repeatedly
  applying `Hint` from the empty grid solves the puzzle in ≤ 49 moves; Core forward of baked `initial`/`trained`
  weights reproduces the golden activations (≤ 1e-6), the untrained guess and the trained "3"; Core accuracy on the
  60 finale digits matches the baked predictions; blame is non-zero and its top wires are stable.

## 9. Draft script (owner must approve before any voice is rendered)

One narrator. Short sentences, no jargon without a picture. `{…}` values come from the bake. Roughly 5 minutes with pauses.

**Region 0, The Page (dock)**
1. Look at this number. You read it instantly. It's a three.
2. A computer can't see it. All it ever gets is numbers.
3. Today you'll watch a machine learn to read it. From the inside.
4. Pull the orange lever, and we'll dive into the picture.

**Region 1, The Grid**
5. We're inside the picture now. Every pixel became one number.
6. Blank paper is zero. Full ink is one. The taller the pillar, the more ink.
7. To keep it simple, we shrink it to seven by seven. Forty-nine numbers. That's all the machine gets.

**Region 2, One Neuron**
8. This is a neuron. It looks at all forty-nine numbers at once.
9. Every pixel has a weight. Plus means: I want ink here. Minus means: I don't.
10. It multiplies each pixel by its weight and adds it all up. If the total passes the line, it fires.
11. Your turn. Paint the weights so it fires for ones, and not for zeros. Tap a square to change it.
12. *(fired for a zero)* It fired for a zero. Zeros have ink around the edges. Try minus there.
13. *(missed a one)* That one didn't fire. Ones have ink down the middle.
14. *(solved)* You found a pattern in plain numbers. That's all a neuron does. Math.

**Region 3, The Network**
15. One neuron spots one pattern. Reading digits takes many, wired together in layers.
16. Forty-nine pixels in. Sixteen hidden neurons in the middle. Ten answers out, zero to nine.
17. Let's send our three through. Watch the light.

**Region 4, Wrong**
18. It says… {WRONG_GUESS}.
19. Wrong. It has never been taught. Every weight is random.

**Region 5, Rewind**
20. So we go backwards. The mistake flows back through every wire.
21. The more a wire caused the mistake, the brighter it burns. That's called backpropagation.
22. Point at the brightest wires to nudge them. *(watch-only cut: "Every wire learns which way to move.")*
23. *(done)* Now every wire knows which way to move.

**Region 6, The Valley**
24. All that blame points one way: downhill. Down here, the network is less wrong.
25. Each step moves every weight a little bit downhill. That's gradient descent. Hold on.
26. *(after the overshoot)* Too big a step. We flew right past the bottom.
27. Smaller steps now. Down… and down… settling in.

**Region 7, Right**
28. Back in the network. Same three. New weights.
29. It says… three. Right.
30. We showed it {TRAIN_COUNT} handwritten digits. Now it reads {TEST_ACCURACY} percent of digits it has never seen.
31. Do the same with words instead of pixels, with billions of weights, and you get the AI you can talk to.
32. That's where we're going next.

## 11. Pitfalls to avoid

- Building region visuals at run time only: edit-mode sheets and seat captures then show placeholders (the old loss
  landscape was a one-sided white plane in the saved scene). Build geometry in the builder from the JSON.
- A network that only reads from inside: design layer spacing and node size for the wide video shot too.
- Panels whose text a camera can circle to see mirrored: give them backs, or keep them where only the seat sees them.
- 49 cell renderers, 944 wire renderers: combine into meshes; colliders are free, renderers are not.
- Narration numbers typed by hand: read them from the bake (the builder can fill `{…}` from the JSON).
- Saying "done" from a log line. Look at the image, run the test, paste the output.
