# ADR-013: Ride v3 Rendering: HoloLit, the Two-Mesh Network, and Per-Camera Quest Overrides

| Field | Value |
|---|---|
| ID | ADR-013 |
| Date | 2026-10-09 |
| Status | Accepted (built and verified in the Editor; not yet measured on a Quest 2) |
| Deciders | Ride v3 work (Ignite plan WP2, WP5, WP6) |

## Context

The v2 ride drew every part with a flat `URP/Unlit` colour, so nodes and the pod read as cardboard. The track was about 190 separate renderers (160 glow quads, 30 ring lines, 2 rails) and the "neural network" was one small diagram. The project's active render pipeline asset is a desktop sample (`PackageSamplesURPAsset`) with the depth texture, the opaque texture, HDR and 2x MSAA all on, which is expensive on the Quest 2's tile GPU. The teacher asked for a bigger, more beautiful network, a more exciting ride, and a view that nothing blocks.

## Decision

1. **`Convergence/HoloLit`** (`Assets/Shaders/HoloLit.shader`) is the shader for the ride's solid parts: unlit cost, a fixed key light in view space plus a Fresnel rim and optional emission. No real-time lights, shadows, or post-processing. It is hand-written URP HLSL, not Shader Graph, so it can be authored and reviewed as text. Icons, glows, plates and lines stay on URP Unlit.
2. **The big network is two meshes and two draw calls.** `NeuralLinks.shader` draws every connection as a camera-facing ribbon built in the vertex shader (never narrower than 1.6 px, never wider than 4 px, so far lines fade instead of shimmering); `NeuralNodes.shader` draws every neuron, speck of dust, haze cloud and the finale orb as billboards. The geometry is generated by `Tools/Editor/NeuralRideBuilder.Network.cs` (7 layers, 54 neurons, stops docked at layers 2, 4 and 6, fixed seed) and saved as mesh assets that the builder **recreates** on every run (updating a loaded mesh asset in place leaves the Editor drawing stale GPU data).
3. **Honest by design:** the builder runs a real forward pass (tanh of weighted sums) and bakes it into the meshes: link width and brightness are |weight x input|, neuron size follows activation. It is baked at build time, not live.
4. **`NeuralCoreView`** (Presentation) feeds three numbers to those shaders: how far the light has reached, an ignite flash, and a flow clock. Solving a stop lights the network around it; the outro ignites it all. While a stop is live the network steps back (`RideTheme.stopFocus`), so the teaching panels stay readable.
5. **The ride camera overrides the shared pipeline asset per camera** (`NeuralRideBuilder.BuildScene`): depth texture off, opaque texture off, HDR off, post-processing off, no extra AA. The shared asset and the Level 01 scene are untouched.
6. **Panels are placed by angle from a normalised eye** (`Polar` and `Face` in `NeuralRideBuilder.Pod.cs`): eye 1.30 m, viewing cone +-35 degrees across and -20 to +22 up. `PodSeat` lifts the rig so a real rider's eye sits at 1.30 m. `Tools/Editor/RideSightlines.cs` enforces this on every build (sight lines from 1.15, 1.30 and 1.45 m, the cone, text of at least 1.5 degrees) and fails the build on a real problem.
7. **Transparent panels draw in a fixed order** (`_QueueOffset`: glows 2980, plates 2990, then text and icons at 3000), because transparent objects otherwise sort by the distance of their centres and a wide plate dims the text on its sides.

## Consequences

- The network costs 2 draw calls instead of about 190; the whole ride measured 72 to 103 draw calls and about 14k triangles in the Editor (budget 100 and 100k). The real number needs OVR Metrics on a headset.
- A shader edit means a recompile in the Editor, and the shaders have not been run on a Quest (Vulkan, multiview). Test there before Ignite.
- A new panel or label must go through `Polar` and pass `RideSightlines`, or the build fails with a message naming the blocker.
- If the project's URP asset is ever replaced by a mobile one, the per-camera overrides become redundant but harmless.
